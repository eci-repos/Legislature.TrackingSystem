# PM Validation Reports

Status: active

Last updated: 2026-09-04

## Purpose

This folder stores PM Validation reports prepared after a sprint and/or promoted use case is completed and verified.

PM Validation reports are required closeout deliverables. They connect completed scope, source requirements, verification evidence, delivered artifacts, AI metrics, known gaps, residual risk, and the PM validation decision.

## Naming

Use ISO date and scope-specific names:

- `YYYY-MM-DD-sprint-N-pm-validation.md`
- `YYYY-MM-DD-use-case-<slug>-pm-validation.md`

## Preparation Rules

- Prepare the PM Validation report only after the sprint and/or promoted use case scope is completed and verified.
- Reference the applicable source user stories, source requirement IDs, acceptance criteria, tests, traceability records, and delivered artifacts.
- Record AI Metrics for the sprint and/or promoted use case, including model, token, cost, elapsed-time, tool/run, verification, and delivery metrics when available.
- Mark unavailable token, cost, or billing values as unavailable. Do not invent usage values.
- Clearly label cost estimates and include the pricing basis when actual billing values are not available.
- Record known gaps, residual risks, deferred items, and open PM questions explicitly.
- Link the report from the current sprint file and related handoff notes when scope is closed.
- Use `PM-Validation-Report-Template.md` unless the current sprint defines a more specific format.
